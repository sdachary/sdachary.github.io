# Architecture — Portfolio

## Key Decisions
- Vite + React + TypeScript for fast dev experience; single build produces three pages (`index`, `manacitra`, `floweditor`) via Vite multi-page input.
- Static site hosted on GitHub Pages (`sdachary.github.io`) via Actions build (`deploy.yml`).
- Mānacitra is a standalone page embedded on the homepage as an iframe; the flow editor is admin-only and never publicly linked.
- Contact form POSTs to the `portfolio-contact` Cloudflare Worker (`https://portfolio-contact.sdachary-582.workers.dev`), which appends submissions to the Notion "Contact Submissions" DB (`3d758aef-cf9d-8164-9d2c-e3519633dbc8`). The earlier n8n webhook path (`VITE_N8N_WEBHOOK_URL`) was removed — no n8n instance runs.

## Data Flow
```
push → ci.yml (gitleaks, lint, typecheck, test, build)
     → deploy.yml (dist/ → GitHub Pages)
browser → sdachary.github.io (static assets + Plausible cookieless analytics)
contact form → portfolio-contact CF Worker → Notion "Contact submissions" DB
```

## Services
- **portfolio** — the site itself (Vite + React + TS). Homepage sections: Hero, About, Experience, Projects, Mānacitra embed, Contact. L1 legal pages `/privacy.html` + `/terms.html` (DPDP); cookie banner in `public/cookie-banner.js` (informational, essential-only, persisted in localStorage, auto-dismissed on scroll).
- **portfolio-contact** — CF Worker (`worker/src/index.ts`, `worker/wrangler.toml`). Receives `{name, email, message}` POST (CORS: sdachary.github.io + localhost), appends to Notion Contact Submissions DB. `NOTION_TOKEN` is a Wrangler secret (tagged via `wrangler secret put`, not in the repo).
- **Mānacitra** — ops map at `/manacitra.html`. A **1950s cord switchboard** rendered two ways: a real **3D model** (three.js) you can orbit and a **2D tier map** for reading the topology at a glance. Each service carries an icon — a real brand logo where simple-icons has one, otherwise a monoline type-glyph — so each block is distinguishable at a glance. Health reads as lamp state (lit = online, dark = offline). The original isometric SVG plate is kept as build-time geometry only (`figure/world.mjs`, `figure/figure.mjs`) that the audit runs against; it is no longer a user-facing view.
  - **Geometry** — `src/manacitra/figure/world.mjs` (bays, jack slots, cord routes) and `figure.mjs` (drawing) are **pure ESM with no node dependencies**, so the browser builds the same SVG the Node build audits (verified byte-identical). `public/manacitra/keys.json` carries only the audited *painter order*; no SVG is checked in, so a topology change needs no rebuild of a static asset.
  - **Audit** — `node tools/manacitra/build.mjs --audit` runs the anatomy kit's geometry audit (clearance, terminals, folds, self-overlap, depth order, crowding) and exits non-zero on any problem. Current state: **audit passed, zero problems**, with a minimal documented crowd allowlist. `scripts/lines.mjs` reports 0 floating line ends. `tools/manacitra/switchboard*.html` are standalone previews of the same figure.
  - **Runtime** — `figure/live.mjs` (no imports) wires selection, BFS hop lighting with a staggered reveal, a 60 s health poll, the idle tour, and the keyboard path (arrows move the jack focus, Enter traces, Escape clears). Health only flips `data-state`; the geometry is never rebuilt.
  - **Mount** — `Manacitra.tsx` is a thin React shell: fetch `data.json`, then render the map or the lazily-loaded model from it. Selection, hover and health are lifted into the shell so the map, the model, the rail and the card stay in step.
  - **Usable, not just pretty** — the drawing is a diagram; the chrome beside it carries the facts. A **rail of all 30 jacks by name** grouped by tier (`ui/ServiceRoster.tsx`, each row icon + lamp) and a **service card** (`ui/ServiceDetail.tsx`: icon header, state, check time, description, protocol / data stored / PII / topology, wired-to). The list and the picture are two views of one selection: hovering a row marks the jack, clicking either side selects on both and (in the model) zooms to it, and a hover tooltip names a jack. Below 900 px the roster moves under the drawing.
  - **Model view (three.js)** — the owner asked for a model you can turn over. `scene/Model3D.tsx` rebuilds the *same* `world.mjs` layout as meshes: bay panels, 30 jacks (ring + hole + lamp + glow sprite), 20 cords as `TubeGeometry` along the real routes with a plug lead from each jack face, the home box and desk. `OrbitControls` (drag orbits, wheel/pinch zooms, damping), raycast picking (a drag ending on a jack does not select), CSS2D tier labels. The scene is **built once from topology; health and selection only touch materials**, and the render loop is **demand-driven** (damping, focus glides and resizes set a dirty flag; an idle board costs 0 GPU). `focus(svcId)` glides the camera along the current viewing angle. A Model/Map switch in the toolbar picks the view (persisted in `manacitra_view`); Map is the default landing (it needs no three.js) and the model chunk is lazy-loaded so first paint stays fast.
    - **Screen-printed faces** — every panel face carries its services' mark + name as a `CanvasTexture` (6 px per world unit), drawn once at build time. Ink scales with the surface, so leaning in sharpens it, and unlike a DOM label it can never orbit through the back of the board. It reuses `logoFor` / `glyphFor` / `tint` from `ui/ServiceIcon.tsx`, so the model and the map always agree on a service's mark. `fitLabel()` fits the *whole* pair — mark, 2.5 gap, name — inside the 30-unit cell: capping only the text let a long name plus its logo spill into the neighbour's column, so "Sadhan" + "Vishwakarma" read as one word. Type shrinks first (a long name stays legible small), the mark gives way last; it is exported as a pure function precisely so it can be tested without a canvas (`src/__tests__/manacitra-fit-label.test.ts`).
    - **Light and materials** — `RoomEnvironment` IBL (procedural, no asset) so the dark board has something to reflect instead of reading as one black mass, plus a single key light with a PCF shadow map (`PCFSoftShadowMap` was removed in three r186) and countersunk screws at each panel corner. Theme drives `toneMappingExposure`, ambient level and `envMapIntensity`; the light board is deliberately the dimmer of the two — the first pass blew its white panels out to flat paper.
    - **Board palette** — `Manacitra.tsx` imports `ISO_CSS` from `src/iso/iso-kit.mjs` and renders it once inside the `.iso` root. Without it every `var(--anatomy-*)` in `manacitra.css` resolves to nothing and both themes fall through to the portfolio's cream body — two themes on one screen. `PAGE_CSS` is deliberately *not* imported: its `body`/`*{box-sizing}` rules would clobber the app. `iso-kit.d.mts` exists only so `tsc` can resolve the `.mjs`.
  - **Tier map (the reading surface)** — `ui/TierMap.tsx`: five labelled tier columns in the plate's wall order (edge → data → AI → external → home), one pill per service with its lamp **and its icon**, one curve per connection labelled with its protocol. Plain SVG in React, no dependency. Routing keeps it legible: forward wires run through the column gap (labels fanned apart where several share one), same-tier wires loop outside their column, backward wires each take their own lane *below* the board, and a connection whose far end is a zone (`to: "oradb"`) lands on that tier's edge rather than a service. Labels carry a page-coloured halo (`paint-order: stroke`) so they read where wires cross under them. Hovering warms a service's wires; clicking selects on the map, the rail and the service card at once. It mounts and unmounts with its tab, so it costs nothing when hidden.
  - **Per-service icons** — `ui/ServiceIcon.tsx` gives every block a distinguishing mark: a **real brand logo** when `logos.ts` has a simple-icons entry (redis, pihole, tailscale, postgres…), otherwise a **monoline type-glyph** drawn in `currentColor` (so it reads on both the dark and light board) keyed off the service's `type` (database, api, auth/shield, dns, network, monitoring, host, ai, mail, terminal, scm). The 9 own-apps have no brand, so they resolve to their type's glyph rather than an invented mark. Rendered in the **map pills**, the **rail rows**, and the **detail card** header. `scripts/lint-manacitra.cjs` carries the same glyph-key set so type-keyed services don't warn.
  - **Light board flow (build-time figure)** — kept in the geometry pipeline even though the plate is no longer a view: on the light board a live cord *glows*, but the same amber on paper reads flat, so the light board shows current travelling via a dashed `tb-flow` centreline along every cord, dash phase offset by the cord's cumulative projected length so the run of light stays continuous across the ~5 pieces each cord is drawn in. The flow layer is `opacity:0` outside `[data-theme="light"]` and off under reduced motion. This lives in the build-time figure (`figure/figure.mjs`); it is not rendered by the live model or map.
  - Dropped with the flat map: FilterPanel, LayerToggles, ambient audio, TouchControls, SceneDescription, InfoPanel, FlatMap, `layout.ts` (+test). Kept: contrast toggle, reduced-motion, and search — retargeted to "find a jack" (type a name, it selects the jack and lights the route).
  - React Flow canvas editor at `/floweditor.html` (internal admin only, no public link) — node positions persist to localStorage, an "Export data.json" button downloads the full data with per-service `pos {x,y}` as a hand-review PR payload.

## Integration Points
- GitHub Pages — hosting; deploy from `.github/workflows/deploy.yml` (build + upload-pages-artifact + deploy-pages); CI from `ci.yml`.
- Cloudflare — the `portfolio-contact` Worker (contact form → Notion). Site hosting is GitHub Pages only.
- Plausible — cookieless analytics (`script.outbound-links.js` in `index.html`).
- oradev (systemd timers) — `portfolio-sync.timer` runs `scripts/sync-activity.sh` daily (sources Recent Activity from the Paca API "Done" column, not public GitHub events); `manacitra-sync.timer` runs `scripts/sync-manacitra.sh` weekly (pulls repo, regenerates `public/manacitra/data.json` from live zone/service probing).
